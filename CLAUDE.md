# ISIMIP Climate Data Pipeline - Development Guide

This codebase pulls, processes, and validates ISIMIP climate model data for two distinct downstream products. Each product has its own processing logic, output format, and tooling. Workflows are consistent within each product class but differ across them. **Never confuse them.**

## Two Data Products

### 1. TCFD / CDP Reporting (8 value classes, annualized)

Processes ISIMIP data into annualized decadal statistics for physical climate risk assessment.

- **Purpose**: TCFD and CDP climate risk disclosures (timber, fisheries, health, agriculture, drought, tropical cyclones, wildfire, soil/subsurface carbon, etc.)
- **Output**: `{variable}_{scenario}_processed.nc` — 8 value classes (median, percentile, trend, **trend_pvalue, trend_tau, trend_n_obs**, lower_ci, upper_ci), plus per-cell `n_members`/`n_models` and any layer-specific extras
- **Tooling**: `isimip-pipeline` CLI + `scripts/process_*.py` (e.g., `process_qg.py`, `process_fish_b30cm.py`, `process_led_drought.py`, `process_let_cyclone.py`, `process_burntarea_fire.py`, `process_csoil_soilcarbon.py`, `process_fldfrc_flood.py`)
- **Skills**: `/isimip-search-download`, `/isimip-process-visualize`, `/isimip-extract-aggregate`
- **Visualization**: `scripts/generate_maps.py` (diverging trend/change maps auto-reverse to red=worse when a processed file sets `percentile_direction: higher_is_worse`)
- **Key concepts**: Shared 2020s baseline, adaptive windowing, kernel smoothing, Theil-Sen trends, percentile-of-score ranking
- **`trend` is a THEIL-SEN SLOPE of the DECADAL MEDIAN series** (standard from 2026-07-30, user decision). Expanding window from the baseline decade to each target decade, in **value per decade** — via `trend_significance.theilsen_decadal()`, which fits against the decade index so **no rescaling is applied** (multiplying by `window_years` would inflate every trend 10×). It supersedes **three** earlier definitions: a within-decade annual slope (too noisy), the baseline-anchored two-point rate (no residual → no p-value), and — rejected the same day — Theil-Sen on the **annual** series, which is **catastrophically wrong on zero-inflated hazards**: Theil-Sen is a *median* of pairwise slopes, so where most year-pairs are 0→0 it returns **exactly 0**. That hit **91.3% of `driedarea` ssp126 cells**, with 25.1% of ssp585 cells pairing `p<0.05` with a zero slope. The decadal series cuts it to 10–14% — a **reduction, not a cure**, so QA warns when a zero slope coincides with a significant p-value. Consequences: the **baseline panel is NaN, not 0**; **`trend × elapsed_decades == change map` no longer holds** (do not reinstate that check); and `trend` (decadal) and `trend_pvalue` (annual, far better powered) are deliberately fitted on **different series**, so sign agreement is 87–97%, not 100%. Declare `trend_method: theil_sen_on_decadal_median_series` — `generate_qa_report.py` selects its invariants from that, and detects it from `trend_method` **before** the prose, because the provenance string itself contains "baseline-anchored" in the sentence denying it. See GUARDRAILS.md §10.
- **Trend significance is MANDATORY on every layer** (added 2026-07-30 — before that no layer carried one, while `export_formatter.py` and the legacy 28-column schema both expected `Decadal_Trend_Significance`, so it silently resolved to NaN and read as "not significant"). Emit `trend_pvalue` / `trend_tau` / `trend_n_obs` from `scripts/utils/trend_significance.py`; never hand-roll the test. Method: **two-sided Mann-Kendall on the ENSEMBLE-MEAN ANNUAL series**, expanding window anchored at the 2020s baseline, so the 2030s panel tests 2020–2039 (n=20) and the 2090s tests 2020–2099 (n=80); the baseline panel is NaN (no elapsed period). **Members are averaged WITHIN each year, never stacked as independent observations** — stacking lets between-model level offsets dominate the sample (68.7× the interannual SD on `csoil-total`, which collapses detection from 83.0% of land to 14.4%) and would let `trend_tau` contradict `trend`. Ties are tie-corrected, not ignored (65.5% of `driedarea` cells have a tied series). A constant series gives **p=1.0, not NaN**. The p-value measures monotonicity of the ensemble MEAN, **not inter-model agreement** — `csoil` reaches p<0.05 on ~80% of land at ssp585 while its sign is contested across models; agreement lives in `lower_ci`/`upper_ci` and `n_models`. Risk direction = `sign(trend_tau)` combined with the layer's `percentile_direction`. Backfill an existing layer with `scripts/backfill_trend_significance.py {layer_id}` (`--check-only` first); it reuses each processor's own `parse_name`/`load_member`, gates on reproducing the published `median`, and asserts every pre-existing variable is bit-identical **except `trend`**, which it deliberately REPLACES (see `REPLACED_VARS`) and which it requires to have actually changed while the file still declares the old anchored method. **Regional aggregation must recompute** MK on the area-weighted annual series via `mk_pvalue()` — averaging per-cell p-values is meaningless. See GUARDRAILS.md §15.
- **Lange 2020 exposure family** — **TWELVE variables, not six** (corrected 2026-07-28): `le{d,r,w,c,h,t}` = **land area** fraction exposed, paired with `pe{d,r,w,c,h,t}` = **population** fraction exposed (`ped`/`per`/`pew`/`pec`/`peh`/`pet`, previously undocumented). Hazards: `d` drought, `r` river-flood, `w` wildfire, `c` crop-failure, `h` heatwave, `t` tropical-cyclone — ISIMIP2b annual, rcp26/rcp60; enumerated in `config/isimip_search_catalog.yaml` → `drought.exposure_lange2020.family` + `population_twins`. Files are **`.nc4`, not `.nc`** — a `.nc` glob returns zero and reads as "no data". `lec` is published by `pepic` as well as `gepic`. An SSP-era sibling **does** exist under a different publication name (`Heinicke2026` `driedarea`), so "no ISIMIP3b version of this family" was true only of the publication, not the science. The decadal statistic is the **mean** (exposed-area frequency/fraction), never the median. **Data nature varies by member and MUST be value-checked, not assumed** — `led` is a **binary** {0,1} per-cell flag; `let` is a **continuous fraction** [0,1) (both verified). Dedicated processors (`process_led_drought.py`, `process_let_cyclone.py`); `process_qg.py` cannot be reused (it parses GCM from filename field [1], but lange2020 puts the impact model there). For **thin ensembles** (e.g. `let` = 1 model × 4 GCMs), apply **5×5 exponential-decay spatial smoothing** to per-member decadal maps to borrow strength from neighbors. For **zero-inflated** hazards, use a **two-tier percentile** (zeros→1; non-zeros ranked vs the non-zero 2020s baseline → [2,100]). CIs = mean ± 1 inter-member SD, clamped. See WORKFLOW-ISSUES.md 2026-07-24 and GUARDRAILS.md §8–§10.
- **Wildfire has several representations** — don't conflate them: the Lange 2020 `lew` *exposure* member (above; rcp26/rcp60 **only**, no rcp85), the `ffire` carbon-**emissions** flux, the ISIMIP3a-only `fire`-sector diagnostics (`firesize`/`firenr`/`fireints`/…, historical only — an evaluation reference, never a layer source), and the **direct `burntarea` burnt-area fraction**, which is the one processed. **Since 2026-07-28 the layer is ISIMIP3b `biomes` `burntarea-total`, ssp126/370/585** (it was ISIMIP2b/RCP before; newer round and scenario family win wherever the newer data is viable). `process_burntarea_fire.py`: **12 members/scenario** = `mc2-usfs` (annual, 5 GCMs) + `visit` (monthly, 5) + `classic` (monthly, 2); raw %, **no normalization** (same unit *and* within 1.6×), **no spatial smoothing** (thick), shared 2020s baseline (3b starts 2015 → no 2010s decade). `trend` is a **Theil-Sen slope of the decadal medians, 2020s→decade (GUARDRAILS §10; supersedes the baseline-anchored rate 2026-07-30)**, % decade⁻¹ — **not** a within-decade slope (fire is too noisy year-to-year) and no longer proportional to the change map. 11.6–10.8% of cells return an exactly-zero slope (Theil-Sen tie residual); QA reports it. Three traps: **monthly burntarea annualizes by SUM, not mean** (burnt area *accumulates* — verified against `classic`'s daily output, 1e-6 agreement; the csoil mean-annualization precedent is wrong here and would under-scale 12×); **annual values legitimately exceed 100%** where a cell reburns, so the CI is floored at 0 and **unbounded above** (clamping to 100 would push `upper_ci` below the median); and **`classic` runs at an effective 1.0°** (100% constant 2×2 blocks) — kept deliberately, while **`elm-eca` is EXCLUDED** at ~4°×5°. Also note the **declared unit cannot gate pooling**: 2b `clm45`/`orchidee` declare `%` while sitting ~1000× low on a 0–1 fraction scale. Emits **`n_members`/`n_models`** per cell (the 3 models don't share a land mask). See WORKFLOW-ISSUES.md 2026-07-28 and GUARDRAILS.md §9–§11.
- **Timber growth productivity, temperate needleleaf evergreen conifers (the Sitka-spruce use case)** — **two ISIMIP2b `biomes` layers**, `timber_cveg-tempnle_annual` (**kg m⁻²**) and `timber_npp-tempnle_annual` (**kg m⁻² yr⁻¹**, converted from `kg m-2 s-1` on the members' own 365-day calendar), both from `process_timber_tempnle.py {cveg|npp}`. **Why 2b, not 3b**: **no PFT-resolved `cwood` exists anywhere in 2b** (all 11 biomes models *and* the permafrost sector checked), and **no climate-zone-resolved conifer PFT carries `cwood` in ANY round** — 3b has `cwood` only for the all-climate classes (`classic` `evgndltr` 2 GCMs, `jules-es-vn6p3` `ndlevg` 5 GCMs), which pool boreal with temperate conifers (**34.6%/29.3% of their global PFT wood sits at 55–70°N**). User chose PFT specificity over the wood-only pool; wood is p50 **77–90%** of conifer `cveg`, so `cveg` is a damped wood surrogate, not a different signal. Pooled: `orchidee` `tendev`(4 GCMs) + `orchidee-dgvm` `tendev`(2, no rcp85) + `clm45` `needleleaf-evergreen-tree-temperate`(ragged) + `lpjml` `temperate-needleleaved-evergreen-tree`(4, **npp only** — no cveg per PFT) → **cveg 8/8/6, npp 12/12/10** at rcp26/60/85. **`caraib` `ndevteclt` is EXCLUDED** (~1–2° effective grid, per-gridcell convention, no rcp85) but ingested as a sensitivity panel; its codes carry **no `long_name`** and were identified by biogeography (`ndevteclt` temperate; **`ndevtecdt` is BOREAL despite "te"**). **THREE traps unique to PFT fields** (GUARDRAILS §13): values come in **two conventions** — per-tile density (`orchidee`/`dgvm`/`clm45`) vs per-gridcell (`lpjml`/`caraib`), harmonized to **per-tile** (the stand-level "what would conifers carry here" framing, and the only option that retains `clm45`, which publishes **no cover fraction at all**); `lpjml` is divided by cover with a **1% floor**; and **`pft-` unit labels lie** (`classic`/`orchidee` declare `%` but store 0–1). Harmonizing collapses the apparent spread from **10.5×/177×** to **2.35×/1.83×** on a common mask → **no normalization**. **Mask rule: ≥2 model FAMILIES** (`orchidee`+`orchidee-dgvm` = one family) — the pooled level differs **12×** between multi-model and single-model cells, so the union would print mask edges and distort the percentile. Note this degenerates to "all models" for cveg, which has only 2 families. **Composition varies by scenario**, so the 2020s panel is pooled **per scenario** and is *not* bit-identical across them — an all-member baseline manufactured a **−0.72 kg m⁻²/dec** rcp85 loss with a fake recovery. **`higher_is_better`** (risk = declining growth); trend = Theil-Sen slope of the decadal medians, 2020s→decade (GUARDRAILS §10; supersedes the baseline-anchored rate 2026-07-30); npp CI **not floored** (npp is legitimately negative). Signal: growth **rises** with forcing in these models (2090s trend +0.085/+0.154/+0.177 kg m⁻² dec⁻¹). **No Picea sitchensis exists in ISIMIP** — species-level forestry is 8–9 European stand sites, nearest congener `piab`. See WORKFLOW-ISSUES.md 2026-07-28 and GUARDRAILS.md §8–§9, §11, §13.
- **River flooding — `fldfrc` flooded-area fraction, THREE parallel layers by protection level.** `riverflood_fldfrc-{none,100yr,flopros}_annual`, from ISIMIP2b `DerivedOutputData/Zimmer2023` (CaMa-Flood v3.6.2, Willner `flood-processing`), **rcp26/60/85**, **24 members/scenario** (6 GHMs `clm45/cwatm/h08/lpjml/matsiro/watergap2` × 4 GCMs; `clm50`/`mpi-hm`/`pcr-globwb` are historical-only). Processed by `process_fldfrc_flood.py`, ingested by `download_fldfrc_flood.py`. **Native 150 arcsec (~4.6 km), coarsened area-preservingly to 0.5° at ingest** — exact 12×12 block sum (alignment 1.4e-14°, area-conserving <1e-9), denominator = **full cell area**, so `sum(median/100 × cell_area)` over any region *is* the flooded km². **The protection level is the layer's biggest choice, not a detail** — same member, 2020s→2090s global flooded area: `none` +2.9% (saturates on routine seasonal wetting → no risk signal), `100yr` **+92.4%**, `flopros` +51.9%. Protectiveness runs `none < flopros < 100yr`; **`flopros` is NOT a proxy for "unprotected"** (it retains only 19–36% of the undefended signal even in the least-defended regions), so read `100yr` as a **severity threshold** that needs no defense database. Decadal **mean** (never median — a single year is ~93% exact zeros); trend = Theil-Sen slope of the decadal medians, 2020s→decade (GUARDRAILS §10; supersedes the baseline-anchored rate 2026-07-30) — fitted on the DECADAL series precisely because that ~93% annual zero mass makes an annual Theil-Sen return exactly 0 almost everywhere, and because annual flooded area swings **17×** between adjacent decades; two-tier percentile; `higher_is_worse`; no normalization; no smoothing (24 is thick); CI clamped to **[0,100]** — safe here because flooded fraction is a *bounded* share, unlike burntarea's cumulative %. Coverage 62,066 cells = **95.7% of land excl. Antarctica** — a normal ISIMIP land mask; emits `floodplain_fraction` + `n_members`/`n_models`. **Don't reach for the other flood products**: raw `water_global` has **no** inundation variable in either round (`maxdis` in 2 of 17 2b models, 0 of 3b), and ISIMIP3b `Heinicke2026` `floodedarea` is **binary {0,1}** despite declaring "Exposed Area Share" — binarising at 0.5° overstates area **17–28×** and its mask covers 94.7% of the globe *including ocean*. `ler` ≈ the `100yr` level pre-aggregated (mean ratio 0.99) but has no rcp85. See WORKFLOW-ISSUES.md 2026-07-28, GUARDRAILS.md §9/§12, and catalog `search_results.flooding`.
- **River flooding, 4th layer — the 1-in-100-year EVENT** (`riverflood_fldfrc-event100yr_annual`, `process_fldfrc_event100yr.py`). The three protection layers are all *expected-annual-area*; this one is **event frequency + event footprint**, derived from the paired `none`/`100yr` annual series (no new download). **It is NOT `none` + `100yr`** — that double-counts, because `100yr` is a **subset** of `none`, not its complement: `100yr > none` in **0.000%** of cells, and where `100yr > 0` it *equals* `none` in **84–88%** of them, so the sum exceeds 100% of a cell in up to 28,139 cells (impossible for an area fraction) and lands 17% *below* the true footprint anyway. Correct construction per member/decade: frequency = years with `100yr > 0` ÷ valid years; footprint = mean of `none` over exactly those years. **`median` carries the FREQUENCY, not the footprint** — the footprint is nearly static (**+1.8%** 2020s→2090s at rcp85, topography fixes a given flood's extent) while frequency **more than doubles (+122%)**: the preindustrial 1-in-100 flood becomes a **1-in-5.7-year** flood. Making the footprint primary would ship a confidently flat layer. This also explains the siblings — `none` saturates (+5.1%) and `100yr` explodes (+225.5%) because **all four layers are measuring a frequency change**. Two caveats in `known_issues`: "1-in-100" is **preindustrial** (GEV fit to `picontrol`/`1860soc`, so the 2020s already sit at ~1-in-15), and the conditional mean is **selection-biased upward** (cells never exceeding in a decade are excluded) → trust the *ratio*, not the level. `event_footprint` has thinner, more variable depth than the frequency → qualify it with **`n_members_footprint`** (median 13 of 24), not `n_members`.
- **Drought — `driedarea`, the SHIPPED drought layer (ISIMIP3b/SSP).** `drought_driedarea_annual`, from **`DerivedOutputData/Heinicke2026`** — the SSP-era sibling of Lange 2020 `led`, **ssp126/370/585**, **15 members/scenario** (3 GHMs `h08`/`jules-w2`/`watergap2-2e` × 5 CMIP6 GCMs, uniform `2015soc/default`), annual 2015–2100. It **supersedes `led`** — newer round and scenario family, consistent with the wildfire and soil-carbon layers. Processed by `process_driedarea_drought.py`; ingest via `download_driedarea_drought.py`. **BINARY {0,1}** like `led` (verified across all 45 members), so the decadal statistic is the **mean** (= drought frequency), never the median — and it is an *occurrence frequency*, **not a within-cell area share**: area affected is a downstream derivation (cell area × frequency) that assumes the whole cell is affected when flagged. Hazard = root-zone soil moisture below the 2.5th preindustrial percentile for ≥7 consecutive months, annualized as the monthly **maximum**. Three traps: the filename puts model/GCM at fields **[0]/[1]**, not `led`'s [1]/[2], so the `led` parser mis-keys every member; the three GHMs **do not share a land mask** (union 63,455 / intersection 46,024 cells — the **union is kept**, nothing filtered, with per-cell `n_members`/`n_models` emitted); and the baseline's exact-zero mass is **3.59% on the union but 0.18% on fully-covered cells**, so burntarea's automatic >2% two-tier switch would fire on a *coverage artefact* — **single-tier is applied by decision**, leaving a visible percentile floor of 3.59. Baseline-anchored trend (binary-derived frequency is far too noisy for a within-decade slope), no smoothing, `higher_is_worse`. Global-mean frequency 2020s 0.0707 → 2090s **0.0954 / 0.1687 / 0.1920** (+35 / +139 / +171%). The all-land layer is intersected with forest cover **downstream at extraction time** using `landuse-forests-and-natural-vegetation` (fixed `2015soc`, grid-identical) — see the catalog's `drought.forest_cover_weight`. See WORKFLOW-ISSUES.md 2026-07-28 and GUARDRAILS.md §8–§11.
- **Soil / subsurface carbon storage** — `csoil-total` (soil organic carbon, ISIMIP3b `biomes`, **kg C m⁻²**), processed via `process_csoil_soilcarbon.py`. **17 members/scenario**: 4 of the 5 models that publish it — `classic`(2 GCMs)/`jules-es-vn6p3`(5)/`mc2-usfs`(5)/`visit`(5) × ssp126/370/585. `visit` publishes csoil-total **only monthly** and is annualized by the **mean of each year's 12 months** (verified immaterial: within-year CV 0.11%). **`elm-eca` is EXCLUDED** — it declares 0.5° but is effectively **~4°×5°** (seams every 10 columns / 8 rows) and has the fattest tail, so it rendered as large bright rectangles; dropping it cost 5 land cells (0.01%). See `EXCLUDED_MODELS` and GUARDRAILS §11. Note the round-dependent name: ISIMIP**2b** uses bare `csoil`, ISIMIP**3b** uses `csoil-total`. The direct **storage** pool — distinct from the vegetation pools `croot`/`cvegbg` and the net-sink **flux** `nbp` (sequestration rate, 3b-only). **`higher_is_better`**: stored carbon is an asset, so the risk is **loss** (percentile **inverted**; red = decline). Shared unit, medians within 1.8× → **no normalization** (model democracy); no smoothing (thick); trend = Theil-Sen slope of the decadal medians, 2020s→decade (GUARDRAILS §10; supersedes the baseline-anchored rate 2026-07-30). Also emits **`n_members`/`n_models`** per cell — the 4 models do **not** share a land mask, so ~81% of land carries all 17 members and 9.2% is single-model; those cells are **kept, not masked**. **Mixed CO₂**: `jules` publishes only its fixed-2015-CO₂ run — and contrary to the old note this does **not** mute its trend, it gives `jules` the **strongest loss** (−4.4% at ssp585) while the four transient models run flat-to-positive. Ensemble membership drives the headline: `jules`'s weight fell 42%→29%, and the global mean by 2090s is now **+2.81/+1.18/+0.72%** (ssp126/370/585) vs the 12-member run's +1.1/−1.4/−2.2%, which reproduces exactly from the same files — so this is membership, not processing. Read the sign as **contested across models**. Layer begins at the 2020s baseline (3b starts 2015). See WORKFLOW-ISSUES.md 2026-07-27/28 and GUARDRAILS.md §8–§9, §11.

### 2. Water Risk Index (20 value types, monthly)

Processes monthly ISIMIP data for 6 water variables into per-month ensemble means plus annual quantile breakpoints, feeding a dedicated Water Risk Index product.

- **Purpose**: Water risk scoring (total water storage, discharge, runoff, evapotranspiration, soil moisture, precipitation)
- **Output**: `C:\Cai_data\WaterIndex\waterIndexUnderlyingData_{var}_ssp.nc` — dimensions `(lat=360, lon=720, scenario=3, value_type=20, decade=9)`
- **Tooling**: Standalone scripts only (NOT the `isimip-pipeline` CLI)
- **Key concepts**: Per-month ensemble means (vt 0-11), annual mean (vt 12), annual quantile breakpoints Q05-Q95 (vt 13-19). Quantile annual aggregation always uses mean (not sum) to keep vt 13-19 in same units as vt 0-12. No trends, no percentile scoring, no kernel smoothing.
- **Normalization**: Robust z-score per impact model (median/IQR from 2015-2024 reference period → target mean=1000, SD=200) applied before ensemble averaging **only when model scales diverge significantly** (e.g., TWS). Per-variable decision documented in memory.
- **QA/QC**: `validate_water_tws.py` (quantile ordering, annual mean consistency, seasonal sanity, cross-scenario checks); `compare_water_index.py` (trend-focused RCP vs SSP HTML comparison with Theil-Sen slope maps and spatial Spearman R²)
- **Units**: Output units match the original RCP files for each variable. See `config_water_variables.py` for per-variable `unit_conversion_factor`.

|----------|-------------|--------------|-------|
| tws | **mean** | kg m-2 (normalized) | Stock; 4 models, normalized to synthetic units |
| rootmoist | **mean** | % max capacity | Stock; WEB-DHM-SG only (÷1187.29 × 100) |
| qr | **sum** | kg m-2 s-1 | Flux; 4 models, raw ISIMIP units, no normalization |

## Storage: S3 is canonical

**Data lives in S3, never on local disk.** See [STORAGE.md](STORAGE.md) for the full layout contract. Local `data/` and `reports/` directories are gone; the local cache is ephemeral scratch under `/tmp/tcfd-cache` (override with `TCFD_CACHE_ROOT`) and deleting it never loses data.

- **Bucket/prefix**: `s3://climate-ai-data-science-shiny-app-data/TCFD/` (`us-east-2`)
- **All keys are built by `isimip_pipeline/storage.py`** — never hardcode an S3 key.
- **A published layer version is immutable.** Reprocessing creates a new version `v{YYYY-MM-DD}_{git-sha}` (plus `-dirty` on an uncommitted tree). `publish_layer_version` refuses to overwrite an existing version unless told to.
- **Consumers read `…/layers/{layer_id}/current/`** and must call `storage.verify_complete()` first — a version prefix whose `_COMPLETE.json` is absent or mismatched is in-flight or corrupt, never data.
- `_COMPLETE.json` gates `data/` + `layer.json` only. `qa/` and `maps/` live in the version prefix (evidence stays pinned to its data) but are regenerable and ungated, so re-running `generate_maps.py` never invalidates a layer.
- **Credentials**: never pin static `AWS_*` env vars — `storage.s3_filesystem()` drops them so the SageMaker container provider auto-refreshes. Pinning a ~1h token kills long jobs mid-run.

Migrated to S3 so far: `process_led_drought.py`, `process_let_cyclone.py`, `process_burntarea_fire.py`, `process_csoil_soilcarbon.py`, `generate_maps.py`, `generate_qa_report.py`. The remaining `scripts/` still reference local paths and are pending the Python rebuild.

**Every ingest-and-process run must leave reviewable HTML evidence — and the maps are a QA gate, not a deliverable.** A layer is **unreviewed, not verified**, until someone has actually viewed an image of it: distribution statistics are invariant under spatial rearrangement and cannot see a spatial defect (GUARDRAILS §11 — a coarse `~4°×5°` member shipped past a full tabular value-check and 37 algebraic checks). Generating maps is not reviewing them. Do not declare a layer good or run `storage.cleanup_raw` before the maps have been looked at.

The four migrated processors call `finalize_layer(LAYER_ID, version=version)` (`scripts/utils/finalize.py`) straight after `publish_processed_layer`, which emits both derived artifacts: `qa/` (`generate_qa_report.py` — invariant checks + statistics, layer-generic, driven by each file's declared attrs) and `maps/` (`generate_maps.py`). Both are regenerable and ungated, so re-running either never invalidates a layer; `finalize_layer` therefore reports failures instead of raising, since the data is already published and gated by that point. Either can be re-run standalone:

```bash
python scripts/generate_qa_report.py {layer_id} [--version V] [--local-only]
python scripts/generate_maps.py     {layer_id} [--version V] [--local-only]
```

Review order: **`maps/contact_sheet.html`** first — one panel per ensemble member at full 0.5°, which is the only view that can show a spatial defect in an individual member (§11) — then the pooled maps. It is linked from the map index and included in the bundle.

For manual review, grab **`maps/maps_bundle.zip`** (~9 MB) — one object holding the whole interlinked collection, since the S3 console downloads a single file at a time. Unzip, open `index.html`. `qa/qa_report.html` is a standalone page and needs no bundle.
