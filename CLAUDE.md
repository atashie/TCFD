# ISIMIP Climate Data Pipeline - Development Guide

This codebase pulls, processes, and validates climate data — overwhelmingly ISIMIP, and since 2026-08-18 not exclusively (see *Non-ISIMIP sources* below) — for two distinct downstream products. Each product has its own processing logic, output format, and tooling. Workflows are consistent within each product class but differ across them. **Never confuse them.**

## Two Data Products

### 1. TCFD / CDP Reporting (annualized decadal statistics)

Processes ISIMIP data into annualized decadal statistics for physical climate risk assessment.

- **Purpose**: TCFD and CDP climate risk disclosures (drought, tropical cyclones, wildfire, heat, flood, coastal, soil carbon, timber productivity, etc.)
- **Output contract**: [OUTPUT-SPEC.md](OUTPUT-SPEC.md) is authoritative — do not restate it elsewhere. `{variable}_{scenario}_processed.nc` on `(decade, lat, lon)`, carrying `median`, `lower_ci`, `upper_ci`, `percentile`, `ols_slope`, `sen_slope`, `n_members`, `n_models`.
- **A SECOND output contract exists, and the shared verifier rejects it on purpose.** `observational-historical-v1` covers a layer built from an OBSERVED RECORD rather than a model ensemble: no `decade`, no slopes, no `n_members`/`n_models` — **absent, never faked to 1**. It uses scenario code `observed` (no projected layer does) and is checked by `scripts/test_observational_baseline.py`; do not relax `test_shared_baseline.py` to accommodate one. Full contract and integration points in [OUTPUT-SPEC.md](OUTPUT-SPEC.md). Three delivery-time rules ride with it: a delivery **files the observed window under the 2020s label as "current conditions"** and delivers no pre-2020 rows for any layer (decade policy, user decision 2026-08-21; the true window travels in `layers.csv` `temporal_window`); `observed` layers enter the Climate Score only as **constants across every tier and decade** (user decision 2026-08-20), damping the score's scenario/time contrast in proportion to their weight share; and `SCORE-OBSERVED-CONSTANT` is the must-disclose caveat that says so.
- **Non-ISIMIP sources are allowed only where ISIMIP is STRUCTURALLY unable to carry the hazard, and the receipt says which.** The bar is not "ISIMIP lacks it today" but "ISIMIP cannot express it" (tornado: the shear term cannot be formed from surface-only forcing — detail in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md)). Such a layer still records its enumeration in `config/isimip_search_catalog.yaml` under `negative_results`, with `verified_absent_on` and an explicit scope for what was *not* listed. `/isimip-search-download`'s **ISIMIP First** rule is unchanged.
- **Shared statistics**: `scripts/utils/decadal_stats.py` implements the contract; every processor calls it rather than rolling its own. `scripts/process_csoil_soilcarbon.py` is the **reference implementation**.
- **Verification**: `python scripts/test_shared_baseline.py {processed_dir}` after every run — exits non-zero on any contract violation.
- **Customer delivery**: the **`/customer-delivery` skill is the entry point** — invoke it before improvising a client deliverable. It owns the pipeline (1 inputs → 2 CSV + dashboard → **4 caveats → 3a compliance report → 3b bespoke report**), and stage status is stamped into each delivery's `manifest.json`. **Stage 4 runs before Stage 3 deliberately**: the caveat set is an *input* to both reports (each must carry every `must_disclose` entry, enforced in the builder and re-checked by the verifier). **Stage 2 always produces both the CSVs and `dashboard.html`**; a delivery missing either fails `scripts/test_customer_delivery.py`. [ASSET-CATALOG.md](ASSET-CATALOG.md) covers stages 1–2 and **[docs/reporting/](docs/reporting/README.md) covers stages 3–4** — both are reference docs the skill points at; do not restate them here.
- **Reports are two documents from one set of numbers.** `generate_compliance_report.py` is an IFRS S2-spined, **fully deterministic** artifact (mapped outward to CDP 3.1.1, ESRS E1-9, CA SB 261); `generate_bespoke_report.py` composes **facet profiles** with a written narrative. Both read the delivery through `scripts/utils/report_common.py` so they cannot disagree about a number, and both refuse to render without every `must_disclose` caveat. The narrative's claims are enforced, not trusted: an unfilled slot, an uncited paragraph, or a citation that does not resolve fails the build. **Profiles guide the narrative and are never pasted into it** — a report containing `<!--` fails the verifier. Figures are inline SVG with zero JavaScript (`scripts/utils/report_figures.py`); this machine has no PDF toolchain at all.
- **A report section may report NOTHING, and should, where the method has not been agreed with the user.** Deferred decisions live in `report_common.TBD_SECTIONS`, render identically into both reports via `tbd_block()`, and the verifier **fails** any report that publishes a figure whose method is still deferred. **Currently deferred: the IFRS S2 29(c) vulnerable-asset count** — exposure rank and susceptibility to harm are different claims; why, and what was tried, is [docs/reporting/compliance/vulnerability-definition.md](docs/reporting/compliance/vulnerability-definition.md). Err toward an explicit gap over a fast answer. **A measurement quoted in a filing needs a reproduction, not a memory** — `scripts/measure_extraction_sensitivity.py` exists because two footprint figures once had no retained receipt. **Facets accept lists and `region` is validated against the delivered locations** — `assert_region_coverage()` refuses to build if a site is uncovered.
- **A layer scoring DEPARTURE FROM A LOCAL BASELINE must say so in every report, and the registry enforces it.** Such a layer's high score means *"unusual for this place"*, never *"bad in absolute terms"* — which **reverses the ranking a reader expects** while every number stays correct. Machine-enforced: `relative_baseline: true` + `relative_baseline_note` in `config/layer_registry.yaml`, promoted by `generate_delivery_caveats.py` to **`must_disclose`**, both reports refuse to render without it, `load_registry()` fails on a blank note, and it prints as `READ AS RELATIVE:` above the ordinary `NOTE:` in the Stage 1 plan. When flagging a new one, **check whether its siblings are flagged too** — flagging one alone implies the others are absolute. Which layers, and the worked example, are in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md).
- **Every layer is a REGIONAL result (0.5° or 0.25°, per layer), never a site result — and where that gap matters it is machine-enforced.** A site's value is its cell's value; that is wrong for hazards that turn on fine terrain (coastal inundation, temperature thresholds vs elevation). Such a layer sets `resolution_caveat` in its processed file and `generate_delivery_caveats.py` promotes it to **`must_disclose`** — same mechanism as `relative_baseline`, same reason. These layers **screen**; they cannot support a design elevation or an asset-level estimate. Do not confuse coarse *support* with coarse *inputs*, and quote the layer's own measured spread rather than asserting coarseness — the instances and numbers are in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md) *Spatial support*. **A REGIONALLY-OBSERVED layer still publishes on the GLOBAL grid, with the region masked** — restricting the grid instead of the data aborts the whole delivery for any outside site (GUARDRAILS §17). Outside the data region every field is NaN, never 0, so the delivery says `OFF_LAYER_MASK` rather than reporting a low score.
- **A SENTINEL APPLIED ON ONE SIDE OF A TWO-STAGE PIPELINE IS NOT A SENTINEL.** Where stage 1 knows a cell is unusable, it must encode that as *missing*, never let the arithmetic produce a legitimate-looking value — a masked cell that accumulates a count of exactly 0 publishes as real low risk, and **no contract check can catch it** (the defect is semantic, not algebraic). When a mask is decided in one stage and applied in another, **assert the invariant in the second**. Measured instance (599 precipitation cells published as tier 1): WORKFLOW-ISSUES 2026-08-18.
- **Ruling out one estimator's failure mode does not SELECT it.** "Which estimator can fail here" has two halves — check whether the other estimator *actually* failed before defaulting to family consistency. Annual maxima have a structural claim on the robust estimator (heavy tails drag OLS; a median of pairwise slopes shrugs). The measured instance that overruled a consistency default is in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md) *Which slope to read*.
- **A caveat attribute is promoted on being NON-EMPTY, not on saying anything — so never write a negative one.** `LAYER_ATTRS_EXPORTED` decides whether a caveat *can* be delivered; `generate_delivery_caveats.layer_caveats()` publishes any non-`nan` note, so `saturation_caveat: "none — …"` puts a must-disclose caveat reading "none" into both reports. Set the attribute only where it applies and park negative measurements under a name **not** on the allowlist (`saturation_measured` / `sparsity_measured`). When adding any caveat, read the **promotion condition**, not just the allowlist.
- **State the MASK with every share-of-cells statistic.** A percentage whose denominator is unnamed is not a measurement — two masks both called "the ISIMIP3b landseamask" differ by 29%, and Antarctica alone flipped a censoring result 15× (GUARDRAILS §14 has the numbers). Also: a masked array's `.data` still holds `_FillValue`; fill through `.filled(np.nan)` before any comparison.
- **Hazard coverage is declared, positively and negatively.** `config/hazard_taxonomy.yaml` names the hazards a disclosure is expected to address and records which are covered — read it rather than restating a count anywhere. A "hazards not assessed" section is mandatory in every report, and **the family list is OURS, not a standard's**, so reports name hazards covered and not covered and **never quote a fraction**. The file splits `customer_note` (rendered) from `materiality_note` / `blocker` / `isimip_candidate` (internal). Do not swap them.
- **Delivery configuration**: `scripts/generate_customer_delivery.py` + `config/asset_catalog.yaml` (asset type → **0/1 hazard-family score weights** — since 2026-08-20 every delivery carries the full standard set of signed deliverable layers, and the catalog weights only the Climate Score; weights are set with the user in a walk-through, never pre-assigned) + `config/layer_registry.yaml` (layer → disk location and which slope to read). Output is a normalized star schema in gitignored `deliveries/{customer}/{date}/`; the Looker 28-column `Export-Key.csv` contract is **retired** (user decision 2026-08-12). Planning is the default and extraction needs `--run`. An asset type absent from the catalog is an **error, never a default** — and so is one whose weights walk-through has not happened. Shared chart vocabulary lives in `scripts/utils/viz_common.py`; `generate_maps.py` stays the tool for **gridded** layers and the two are deliberately not merged.
- **Tooling**: per-layer `scripts/process_*.py` + `scripts/utils/` (shared statistics, extraction, delivery, viz)
- **Skills**: `/customer-delivery`, `/isimip-search-download`, `/isimip-process-visualize`, `/isimip-extract-aggregate`. **Invoke the skill before improvising.** Any question of the form "what data exists for X / is X available" is `/isimip-search-download` — load it *first*; it carries the enumeration mechanics and coverage facts this file does not, and it is **authoritative over this file** where they disagree. **Start from the skill's publication map, not from a variable name** — derived publications are named after first authors and identified only by their files; entering a path we already know the name of is retrieval, not a search (GUARDRAILS §13).
- **Visualization**: `scripts/generate_maps.py` — six tabs (`Median | Percentile | Trend | Confidence | Anomaly | Members`); diverging panels zero-centred on the 95th percentile of |value| and auto-reversed to red=worse under `percentile_direction: higher_is_worse`. **Every QA/QC map goes in `reports/maps/{hazard}/`**, whatever renders it; observational layers get narrow per-contract renderers because the shared tools key on `decade`. Conventions, renderer roster and browser-payload limits live in the `/isimip-process-visualize` skill. On a raster `go.Heatmap` the payload term is **dtype, not decimal places** — `float32` halves the page.
- **Key concepts**: Shared 2020s baseline, adaptive windowing, pooled (year × member) decadal statistics, dual OLS + Theil-Sen slopes on an expanding window, percentile-of-score ranking
- **Two slopes, not one** — they fail in **opposite** regimes, so neither is safe alone: `sen_slope` collapses to exactly 0 on zero-inflated hazards; `ols_slope` absorbs between-member level offsets as trend when member coverage is uneven (measured +40% bias). Treat **disagreement between them as the signal that a cell's trend is not robust**. Which slope each layer reads is **measured, never inferred** — the per-layer table is in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md), and the full rule set (the censored-field exception where both slopes agree at ~0 and agreement is ambiguous; choosing from failure modes rather than the `sen==0` share; quoting shares over **ACTIVE cells**, never all finite cells) is in [OUTPUT-SPEC.md](OUTPUT-SPEC.md) — read it before reading any slope.
- **Per-layer facts are NOT in this file.** [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md) is the index of what each shipped layer is and how it was framed; the full detail lives in **the processor's module docstring** and its dated **WORKFLOW-ISSUES.md** entry, and the file's own **global attributes** outrank all of them. Read the one layer you are working on; do **not** read the others for comparison unless the task genuinely depends on it — see *Scope discipline* below.
- **A recorded negative is a claim, not evidence — and so is an understated positive (GUARDRAILS §11).** Every negative needs `verified_absent_on: "<date> — listed <URL>"` or the word `UNVERIFIED`; every **capped or paginated** result is `UNVERIFIED` for coverage *in either direction*. A negative about a *code* is not a negative about a *hazard* — re-issues get renamed.
- **Availability questions stop at the inventory.** Report the model × GCM × scenario matrix with cadence, volume and the open decisions, then **end the turn**. No recommendation, no ranking, no `AskUserQuestion` to force a pick — dataset choice is a discussion the user opens. Give your read on the trade-offs when asked. (2026-08-08; see the skill's *Answering "what data exists for {hazard}?"*.)
- **Scope discipline.** When the user asks about **one** hazard, answer within that hazard and judge each option on **its own** properties. Do **not** justify or rank a dataset by reference to an unrelated shipped layer. Cross-layer comparison is warranted only when the user asks, or when it is a real constraint (a shared processor, the OUTPUT-SPEC contract, a guardrail). Precedent from another hazard is a *hypothesis to re-verify*, never a reason to prefer a dataset.
- **Cross-cutting framing rules** (they generalize; the per-layer instances are in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md)): data nature is **measured, never inferred** — from the variable name, its `long_name`, a sibling member, or another layer (GUARDRAILS §9); the measured nature then determines the statistic, CI, and percentile treatment per [OUTPUT-SPEC.md](OUTPUT-SPEC.md). Thin ensembles get 5×5 exponential-decay spatial smoothing — but **the decay length is a per-layer measurement, not a constant**, and so is whether to smooth at all (a **split-half test** settles roughness-vs-noise disagreements). Zero-inflated hazards get a two-tier percentile (zeros→1, non-zeros ranked vs the non-zero 2020s baseline). Variables where a decline is the risk set `higher_is_better` and invert the percentile.
- **Four decadal-statistic branches, not two.** Continuous → pooled median/IQR; boolean {0,1} → pooled mean±SD; **extreme zero-inflation** → `pooled_mean_zero_inflated`; **multimodal ensemble** → `pooled_mean_multimodel`. The third and fourth exist because the median assumes a non-degenerate, unimodal pool, and both failures were measured ([OUTPUT-SPEC.md](OUTPUT-SPEC.md) carries the numbers). Both are **declared** deviations: measure what the median branch *would* have published, record it in `decadal_statistic_rationale`, and get the user's decision — never take either to improve contrast. **A threshold on the central value inherits the branch**, so derive such counts from the **member share**, which is invariant. Each adoption is its own decision on its own measurement and **the count is not a precedent**; which layers qualify is in [DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md).
- **Extreme-event exposure families** — `config/isimip_search_catalog.yaml` and the `/isimip-search-download` skill are **authoritative over this file** for repository coverage. Two generations exist, and the re-issue is named by **hazard word, not `le*` code**. Never conclude a family has no newer-round version without listing `DerivedOutputData/` — **and a family having no re-issue is not the hazard having no newer data** (the newest tropical-cyclone product sits outside `DerivedOutputData/` entirely). List every directory level; scope each absence claim to exactly what was enumerated.

### 2. Water Risk Index (20 value types, monthly)

Processes monthly ISIMIP data for 6 water variables into per-month ensemble means plus annual quantile breakpoints, feeding a dedicated Water Risk Index product.

- **Purpose**: Water risk scoring (total water storage, discharge, runoff, evapotranspiration, soil moisture, precipitation)
- **Tooling**: Standalone scripts only
- **None of the TCFD contract applies here** — no trends, no percentile scoring, no kernel smoothing, no shared baseline. Never carry a decision across the two products.
- **Per-variable attributes** — output path and dims, the 20 value types, the normalization rule, aggregation and units per variable — are in **[DATASET-ATTRIBUTES.md](DATASET-ATTRIBUTES.md)**, with `config_water_variables.py` authoritative for `unit_conversion_factor`.
- **QA/QC**: `validate_water_tws.py` (quantile ordering, annual mean consistency, seasonal sanity, cross-scenario checks); `compare_water_index.py` (trend-focused RCP vs SSP HTML comparison with Theil-Sen slope maps and spatial Spearman R²)

```
└── _deprecated/              # Archived legacy R code
```

**Where a fact belongs.** A *rule that generalizes* goes in this file or GUARDRAILS.md. A
*fact about one dataset* goes in DATASET-ATTRIBUTES.md, and its full detail in the
processor docstring plus a WORKFLOW-ISSUES entry. A *fact a processed file already carries*
goes nowhere — it is read from the file's global attributes at delivery time, so restating
it creates a second source of truth that drifts the moment a layer is reprocessed.

**Single homes for triplicated topics** (2026-08-21): search/enumeration mechanics — the
`/isimip-search-download` skill (GUARDRAILS keeps its numbered rules; this file keeps
pointers). Slope selection and the statistic branches — OUTPUT-SPEC.md, with the measured
per-layer tables in DATASET-ATTRIBUTES.md. When editing one of these topics, edit its home
and fix pointers, never a parallel restatement.
