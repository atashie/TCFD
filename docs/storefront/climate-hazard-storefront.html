Climate Hazard Storefront

decided 2026-08-20 · updated 2026-08-21 repo: TCFD status: QA reviews complete (37/39) · delivery model v2 + 10-site test delivery live · storefront build not started

How the TCFD hazard layers get served to people who don't have access to the laptop: bulk downloads for large customers, a public map explorer, and self-serve analyses — free up to 3 location-asset pairs, keyed up to 1,000 — at near-zero monthly cost. The laptop stays the factory; the cloud is only the storefront.

The decisions

Access model — revised 2026-08-21

Map free and ungated. Self-serve in two lanes: a free, ungated lane under aggressive rate caps — 3 location-asset combinations, for now — and a paid, keyed lane capped in the hundreds of location-assets (1,000 total, for now). Bulk stays gated.

Free surfaces double as lead generation, and the capped lane is the taster that sells the keyed one. Gating at launch = a per-customer key issued by hand — bulk and paid self-serve alike — no auth or payments build until demand exists.

Compute

Google Cloud Run — one scale-to-zero container.

The real pipeline + 1.5 GB of data baked into a ~3 GB image. $0/mo at expected traffic; 5–20 s cold start after idle; capped so it cannot run up a bill.

Bulk format

NetCDF files as-is, plus manifest, checksums, caveats, attribution.

Zero conversion risk; each file's global attributes stay the single source of truth. Other formats only when a customer asks.

One factory, three counters

Architecture

Use case 2 — bulk. Just the data plane plus a download page. Immutable versioned releases (releases/2026-08-20/ + a latest alias) each carry the NetCDF files, checksums, a machine-readable layers.json generated from the registry + file attributes + caveat texts, and the docs. A release id travels into every CSV and map view, so anything a customer quotes in a filing is reproducible against a frozen release.

Use case 3 — map explorer. Fully static. Per-slice rasters pre-rendered on the laptop (~2,000 assets, well under 1 GB); the browser fetches only the selected slice, reads true cell values on hover, and pulls the 8-decade stack on click for a mini time series. Basemap from a free vector source (e.g. OpenFreeMap); MapLibre GL renders.

Use case 1 — self-serve extraction. The web flow preserves the pipeline's two-step contract: submit sites + asset types (dropdown from the catalog; an absent type is an error, never a default) → server returns the resolved plan and warnings → user confirms → run → zip of CSVs + dashboard.html + caveats + README. The delivery verifier runs before the zip ships. Two lanes share this one flow: the free lane accepts up to 3 location-asset combinations under aggressive rate caps; a hand-issued paid key lifts the cap to 1,000 — same code path, one check on the key. At the paid ceiling the run is minutes, not seconds, and the bundle is tens of MB, so the paid lane likely delivers asynchronously (a link when ready) rather than over a held-open request — an implementation choice, still open.

Non-negotiables

Product semantics that must survive the web

  • "Skip the reports" ≠ "skip the caveats." Stage 4 is deterministic — no LLM — so the self-serve bundle always includes the caveat set. Serving CSVs to strangers without it hands them exactly the misreadings the repo machine-enforces against (Iowa outranking the Sahel on cropfailure-3b; quayside = hillside on sealevel-2b).
  • Map cells render as discrete 0.5° rectangles, never interpolated. The blockiness is the honest statement of regional support. Max zoom capped; resolution caveats shown in the layer panel.
  • Must-disclose text renders wherever a number renders. READ AS RELATIVE, resolution screening, and reference-population notes appear in the map layer panel, the bulk manifest, and the delivery bundle — mechanically, from one exported layers.json, never re-typed.
  • Off-mask is "unobserved," never a low score. OFF_LAYER_MASK keeps its meaning in every surface, including map hover.
  • Privacy default: uploaded coordinates are processed in memory and never persisted — site lists are commercially sensitive. Say so on the page.
  • Cost circuit-breakers, not trust: Cloud Run max-instances=2, Cloudflare rate limits in front of everything, billing alerts on day one.

Considered and rejected

Ruled out, and why

Vercel serverless functions for extraction
Re-verified 2026-08-21: Python functions now allow 500 MB, and beta "Large Functions" 5 GB uncompressed — but the processed corpus is 3.1 GB and near-doubled in the past week, the scientific stack adds ~1 GB, and responses cap at 4.5 MB (today's 10-site bundle is already 2.9 MB; the paid lane's 1,000-pair bundles are orders of magnitude past it). Ruled out on trajectory now rather than impossibility.
Vercel Hobby as the site host
Terms, not tech: Hobby prohibits commercial use, explicitly including advertising a service or being paid for the work. Pro is $20/mo — the largest avoidable cost in this plan; Cloudflare Pages is the free, commercial-friendly twin.
S3 / GCS for the data plane
Egress fees (~$0.09–0.12/GB) tax exactly the highest-volume paths: bulk downloads and map traffic.
An always-on VM (~€4/mo Hetzner)
The respectable runner-up: always warm, one comprehensible machine — but a fixed bill plus a server to patch. The container is portable, so switching to this later is an afternoon.
Client-side-only extraction
$0 forever, but re-implements caveats/masks/schema in JavaScript beside the Python source of truth — the second-source-of-truth failure this repo guards against. Revisit only if traffic ever makes it matter.
A cloud VM for processing
Unnecessary: raw data and human-in-the-loop QA keep processing on the laptop. If that changes, rent a big spot instance per campaign and destroy it.

Still open

Open items

  • Water Risk Index: out of scope for v1 — its outputs aren't on disk today and it's a different contract (monthly, 20 value types). Revisit after launch.
  • Hosting fit with ensembleintel.com: the name question is closed — the domain (registered 2026-08-19, Porkbun) and a preview-walled Next.js app on Vercel already exist. The 2026-08-21 revisit — R2-hybrid vs Vercel-primary — is reviewed and undecided; it turns partly on what that app is meant to become.
  • Paid self-serve lane: the lane and its 1,000-pair cap are decided (2026-08-21); its price and key ceremony are not. Hand-issued like bulk at launch. Two consequences of the cap need a design: scaling today's measured 10-site delivery, a 1,000-pair values.csv is ~90 MB and the run is minutes — so the paid lane wants async delivery, and the dashboard (built for ~10 sites) needs a strategy at that scale: per-site pages, an aggregate view, or CSV-only with map links.
  • Traffic assumption: free-tier math assumed tens of runs/day; re-check if expectations are 100×.
  • Key mechanics: hand-issued at launch, for bulk and the paid self-serve lane; formalize (Cloudflare Access or signed URLs) when customer count warrants.
